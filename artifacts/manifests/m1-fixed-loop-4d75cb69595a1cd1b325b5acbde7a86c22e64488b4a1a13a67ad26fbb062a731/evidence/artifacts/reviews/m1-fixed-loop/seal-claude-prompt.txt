1: # Fixed-shape collect/update loop and CPU soak
2: 
3: The new `pokemon_fixed` package compiles complete collection, player-view encoding,
4: action sampling, simulator transitions, same-player GAE, PPO and Adam into one
5: fixed-signature CPU executable. It extends the sealed JAX learner without changing
6: its source or the pinned simulator. Full G2 and G3 remain open; no competitive
7: strength, full-format, GPU or Prime claim is made.
8: 
9: ## Scope and data path
10: 
11: The admitted game remains the public, fixed-set Rattata duel: 64 simultaneous
12: games, two players, at most four turns. The policy remains linear over 59
13: player-history features, with two action logits and a value head. The frozen
14: [plan](../contracts/fixed-loop-v1/plan.json) fixes capacity at 512 decision rows,
15: two PPO epochs and four 128-row minibatch slots per epoch.
16: 
17: Both views are projected before either choice is submitted. The actor receives
18: only `ActorInput(features, mask)`, from the same frozen parameter tree for the
19: whole collection. Targets and terminal scores stay outside this API. Both players'
20: submitted decisions remain in a KO turn even when the second move is canceled.
21: Training decisions and executed moves are counted separately.
22: 
23: Buffers use time/game/seat order `[4,64,2]`. Terminal lanes become padding; validity
24: is separate from the legal action mask. Padded features and numerical inputs are
25: sanitized before arithmetic, including before the model, so even NaN padding
26: cannot affect parameter gradients. Losses average valid rows, and empty
27: minibatches skip Adam completely. Per-player returns use a reverse time scan;
28: there is no alternation of reward sign or bootstrap from a terminal state.
29: 
30: The shuffle recipe is intentionally new: permute all 512 indices, then stably
31: partition valid rows first. Shapes remain fixed even when episode lengths vary.
32: Numerical update parity compares against the sealed learner using this identical
33: valid sample order; it does not claim the old variable-length permutation has the
34: same trajectory. Adam uses a constant table of the reference's host-rounded bias
35: corrections for the first 20,000 steps, then exact FP32 ones. Parameters, moments
36: and optimizer counters are carried through compiled scans.
37: 
38: ## Verification and measurements
39: 
40: **Campaign status: awaiting completion and seal.** Final measured counts, timing,
41: memory and receipt are added only after the corrected two-hour campaign completes.
42: 
43: Acceptance combines comparisons with the sealed collector and learner, poisoned
44: padding tests, zero-gradient/empty-minibatch tests, fused/separate execution checks,
45: legal-action and outcome-feature checks, and exact disk recovery. Three parity
46: seeds each run eight batches; every boundary is freshly loaded and its next cycle
47: compared byte for byte. First-batch actor and target NPZ exports are separate.
48: 
49: Compilation checks use precompiled callables that reject shape/dtype changes,
50: entry-point trace counters, and actual JAX compilation/cache-lookup log events.
51: A real fresh JIT positive control and identical-call negative control must pass
52: before a zero-new-compilation result can be accepted. Warm-up and compilation are
53: outside soak timing. A preliminary run exposed an ineffective log matcher and
54: was interrupted and preserved; it is not evidence of a passing soak.
55: 
56: The operational soak measures complete cycles with host validation and records a
57: second elapsed-time rate that includes aggregation, telemetry, checkpoint I/O and
58: resume audits. The cProfile run is a separate 1,000-cycle host-cost diagnostic;
59: its rates include profiler overhead. Isolated collection/update timings repeat
60: fixed inputs and are not end-to-end throughput. Latency quantiles are upper bounds
61: from a fixed log-spaced histogram, not exact stored per-cycle quantiles.
62: 
63: Memory reporting distinguishes process RSS from device allocator statistics. CPU
64: JAX may provide no device memory statistics; process RSS alone does not certify
65: 15% available system/device headroom. Training buffers, aggregate metrics and
66: checkpoint state have bounded size. Telemetry is streamed to disk once per minute,
67: not accumulated in a Python list. There is no per-update history in the checkpoint.
68: 
69: ## Recovery and provenance
70: 
71: Checkpoints contain exact FP32 parameter/moment bytes, Adam step, policy version,
72: next game ID, cumulative decision/move counts, seed, plan and source/runtime hashes.
73: The random streams are addressed by seed, named domain and game/turn/seat or
74: version/epoch. The update limit keeps uint32 game IDs and int32 optimizer counters
75: within range; cumulative decisions use an unrestricted Python integer.
76: 
77: Publication is atomic with fsync and rename. Only complete whole-episode update
78: boundaries are supported. A collection/update failure discards uncommitted work
79: and restores the last durable checkpoint; this is rollback, not continuation at
80: the crash point. Tests reject partial publication, source/runtime/plan drift,
81: malformed counters and moments. The soak periodically loads a fresh disk checkpoint
82: and compares its next cycle without counting duplicate audit games as primary work.
83: 
84: The admission gate pins the preceding learner receipt, verifies sealed core files,
85: checks dependency/runtime versions and keeps the R7 final reservation unchanged.
86: Admission is checked again at exit. The final seal archives source, tests, review
87: dispositions, runtime receipts, checkpoints, NPZ exports and campaign logs.
88:
