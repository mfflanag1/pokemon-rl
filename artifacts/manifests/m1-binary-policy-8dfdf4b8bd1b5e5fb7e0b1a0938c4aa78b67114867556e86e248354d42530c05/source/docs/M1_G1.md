# M1/G1: CPU learner canaries and the first restricted transition slice

**G1 passes for the declared whole-episode CPU canary mode.** The project now has
a transparent FP32 PPO/GAE learner, deterministic learning diagnostics and atomic
boundary checkpoints. The first fixed-team CPU transition slice also matches
10,000 pinned Showdown reference cases conditional on recorded chance outcomes.
M1's JAX engine and full G2 gate remain open. No Prime resources, GPU or reserved
final-evaluation data were used.

## Learner result

NumPy 2.5.4, Python 3.14.3, Apple M3 Max arm64. A six-state policy/value table keeps
analytic gradients and updates easy to inspect. This is not the future Pokemon
transformer and is not a learned Pokemon policy.

The accepted plan is `contracts/learner-v1/canaries.json`, version 2. Seeds, budgets,
thresholds and hyperparameters were fixed before the accepted run. All runs finish
the fixed budget; first threshold crossings are diagnostics, not stopping rules.

The delayed task compares both players' root choices once at termination: the sole
correct player wins; both correct or both wrong draw. Each receives its own 1/.5/0
score. Distinct optimal actions, interleaved forced decisions and an always-forbidden
root action exercise perspective, linkage and masking. Three decisions per player
mean each delayed update has 384 decisions. Exploration and auxiliary terms are off.
These synthetic targets say nothing about Pokemon playing strength.

Verified checks include:

- Hand-computed GAE/returns and log-ratios within 1e-5, separate terminal/cut cases,
  and rejection of cross-player/episode or backward linkage.
- Identical-policy PPO ratios equal one, including the trainer's first minibatch;
  both clipping branches and analytic policy/value/entropy gradients checked by
  central differences.
- Single-legal-action actor gradient and entropy ≤1e-7; multiple legal replacement
  candidates retain a gradient. Forbidden choices have exactly zero probability.
- No nonfinite logits, probabilities, losses, gradients or Adam moments in the runs.
- Exact restore of subsequent samples, masks, old log probabilities, returns,
  parameters, moments, counters and updates for both tasks.
- Crashes during collection or after one optimizer minibatch roll back to the last
  committed checkpoint, count discarded work and reproduce it. Partial writes
  never replace a complete checkpoint; preserving a stale partial permits new saves.

A complete fresh rerun reproduced **all six checkpoint files and all six training
traces byte for byte**. Timing fields in the run reports are not invariants. Exact
resume is scoped to matching code, dependencies, runtime and platform.

The full regression suite passed **61 Node and 85 Python tests (146 total)**,
including the existing R1–R7 suite, 13 learner checks and six Python/two Node
restricted-slice checks. R7's bound consumers and dataset remain admissible, and
the final reservation hash is unchanged.

The collector only supports whole episodes. The nonterminal-cut formula is tested
with explicit same-player bootstrap values; end-to-end persistent-game cuts and
live simulator/history checkpoints are not implemented. See the [learner contract](../contracts/learner-v1/README.md)
for the optimizer, mask and checkpoint conventions.

## First restricted simulator slice

`gen9-rattata-duel-v1` admits one exact Rattata per side: level 50, male, Serious,
31 IVs, zero EVs, Run Away, no item, ordered Tackle/Quick Attack. The custom reference
format removes Team Preview and enforces Terastal Clause. It is a constructed
fixed-team distribution, not official Random Battles. Both sets are known from
the profile; initialization starts at a joint move request.

The independent Python integer implementation handles priority/ties, normal damage,
critical hits, STAB rounding, HP, PP, KO interruption, terminal outcome and normalized
own requests. Semantic chance inputs are mandatory; it does not sample its own RNG.
The reference wrapper records actual damage rolls directly, because damage amounts
cannot uniquely identify their originating rolls.

All 32 crit/roll combinations match Showdown. Minimum damage is 33 against 105 HP,
so a game ends by turn four; no slot can exhaust its 48/56 starting PP. This exact
scope excludes Struggle, switching, status, items, healing, Tera and transformation
by admission and mechanics, rather than treating their effects as no-ops.

The accepted campaign used **10,000 distinct mechanics seeds**, with independently
derived action tapes. Python checked **31,303 turn transitions and 54,965 damage
events**, with **zero disagreements** in the declared normalized state/request
fields. Reference capture and damage enumeration took 8.059 seconds on local CPU.
That timing is for tiny fixed duels and excludes Python validation; it is not a
full-format collection or learner-throughput estimate.

This is conditional transition parity: the CPU transition consumes the reference's
crit, damage-percent and tie-order outcomes. It does not independently validate
chance-sampler distributions, public protocol/reveal timing, opponent HP display,
R5 history equivalence or the full hidden-information mutation suite. No JAX
implementation exists yet. The slice remains `production_ready: false`; R6's
complete-format support gate remains blocked. See the [slice contract](../contracts/slice-v1/README.md)
for the exact exclusions and source obligations.

## Next step: M1/G2 JAX port of this exact slice

1. Implement fixed-shape batched state/step for this unchanged profile, with explicit
   semantic chance inputs; compare every scalar CPU and reference fixture. Reject
   unsupported fields/actions at admission and preserve KO/PP/order behavior.
2. Add and separately verify categorical chance sampling (1/24 critical hit,
   uniform 16 damage rolls, fair tied order). Predeclare distribution tests and
   family-wise error handling; matching seeds alone is insufficient.
3. Implement the player-view/public-history adapter, including exact own HP and
   reference opponent HP/reveal semantics. Add applicable hidden-state and pending
   commitment invariance probes before calling G2 complete.
4. Port G1 math to the selected autodiff backend and compare gradients/updates
   against this CPU reference. Only then attach a small policy and measure complete
   collection/update cost. Add persistent-game cuts and live checkpoints together
   if whole episodes become too costly.

Keep the first profile fixed while proving the port. Broader mechanics and the
official random-team distribution require separate R6 obligations and profiles.
Local CPU remains suitable for this next correctness work; reconsider accelerator
hardware after a measured batched collection/update loop exists.
