# R1: pinned Showdown reference harness

Implemented 2026-10-10. The first execution step is complete: local whole-team generation, reference battles, player-visible protocol, recorded choices and deterministic replay. This is the Showdown oracle, not a new accelerated simulator.

## Reproduce

From the project root, using the tested Node version in `.node-version`:

```sh
npm run setup
node --test tests/reference/*.test.mjs
npm run smoke
```

For the complete Node/Python suite (`npm test`), first install the contract
dependencies using [R2_CONTRACT.md](R2_CONTRACT.md).

Setup fetches/builds the exact revision in [showdown.pin.json](../showdown.pin.json), installs from its lockfile with dependency lifecycle scripts disabled, and records fingerprints. It refuses an existing checkout at another revision or with tracked/untracked source changes. It rebuilds generated `dist/` from scratch. The upstream checkout and dependencies are reproducible local artifacts excluded from this project's Git changes.

**Pin:** `942cda71d14bf0618bd57991708a2e2734b6daba` — `gen9randombattle`, singles, Pokémon of the Day disabled, no custom formats, no server configuration loaded. Resolved inherited rules, source/lock/license hashes, compiled-tree and PRNG dependency fingerprints, harness source hashes and runtime versions are in the generated manifest. This is a deliberately pinned local configuration, not an assertion that today's public ladder has identical configuration.

The build was exercised twice on Node v25.6.1/npm 11.9.0, macOS arm64. Both builds produced the same compiled-tree hash. Tests and battle replay require no network after setup. Other runtimes/platforms have not been tested. Full episode replay currently requires an identical manifest; cross-runtime portability is future work.

## Commands

```sh
node packages/reference-node/cli.mjs describe
node packages/reference-node/cli.mjs team example-team
mkdir -p artifacts/runs
node packages/reference-node/cli.mjs run example-battle artifacts/runs/example-battle.json
node packages/reference-node/cli.mjs replay artifacts/runs/example-battle.json
node packages/reference-node/cli.mjs worker
```

`run` refuses to overwrite an existing output file. `worker` accepts one JSON request per line and emits one JSON response per line, keeping the process alive. Examples:

```json
{"id":"description","command":"describe"}
{"id":"battle","command":"run_episode","label":"example-battle"}
```

`generate_teams` accepts an explicit `seeds` array; `replay_episode` accepts the saved `episode` object. Responses use `{id, ok, result}` or `{id, ok:false, error:{type,message}}`. Commands execute sequentially. This is an internal R1 interface, not the R2 JSON Schema/Python contract.

## Information and replay contract

- Team generation, mechanics and each baseline policy have distinct seed namespaces. Seeds are canonical 64-digit hexadecimal sodium strings; malformed forms are rejected before Showdown sees them. Policy randomness is harness-owned.
- Teams are generated by pinned Showdown and passed as structured objects, not reconstructed from marginal statistics. The runner checks generator provenance and initial team hashes, including after seat swaps. A separate synthetic privacy test intentionally constructs a hidden-state variation; it is not a generated-team sample.
- `PlayerView` comes only from the player's public/split channel and its own private request. Routing uses Showdown's own `extractChannelMessages`, and a complete battle is compared with its `getPlayerStreams` output. Terminal result payloads and the other player's private request never enter this view.
- Each submitted choice records the request ID, request hash, protocol-prefix length, admissible protocol choices and rejection feedback. The corresponding view can be reconstructed from that player's protocol prefix. Visible admissibility is calculated solely from the request; it does not read battle truth. Numeric protocol slots are **one-based** in R1. The future semantic/tensor codec will define its own explicit mapping.
- A choice forbidden by the visible request fails before submission. An `Unavailable` error means the reference updated its request; the prefix alone is not proof of hidden information. Observably allowed attempts and their updated requests stay in the tape. The captured trapping examples specifically demonstrate a newly disclosed restriction.
- Raw output is retained and separately checksummed. Only exact `|t:|<integer>` protocol timestamp lines normalize for deterministic comparison. Mechanics, private requests and errors remain unchanged. Recorded write boundaries are preserved; setup is one deliberate three-command chunk, then one choice per write. A failed episode is abandoned, never resumed from partially applied input.
- Replay regenerates and validates initial teams, drives the recorded choices against fresh request IDs, and checks observations, action feedback, normalized output and outcome. It does not execute arbitrary `eval`, `editbattle`, reseed or chat commands from a supplied tape.
- A submission safety cap raises an incomplete-battle error. It never manufactures a draw or terminal training example.

The complete episode artifact is **privileged**: it contains both teams, both player channels and raw reference output. It is for replay/audit, not an actor input. Only a selected player's projected view may enter the future policy loader.

## Verification evidence

The **19 passing tests** cover deterministic team regeneration; fixed fingerprint fixtures; repeat execution and tape replay; different wall-clock timestamps; team identity after swapping seats and changing the mechanics seed; full-battle equivalence to upstream player streams; exact HP/private request separation; a real initial hidden-item perturbation; stale requests and command injection; request-visible disabled/trapped choices; malformed/tampered replay artifacts; live divergence after valid envelope checksums; source/build-integrity failures; safety-cap failures; and multi-request JSONL behavior. Independent review and checked resolutions are in [R1_REVIEW.md](R1_REVIEW.md).

The ten-seed smoke campaign completed **823 decisions across 359 original turns**, plus ten exact replays. Two rejected switch attempts in `r1-smoke-8` disclosed trapping, produced updated requests on the same turn and replayed exactly. The report's `score` field is Showdown's surviving-Pokémon count, not a policy strength metric. No strength comparison or accelerated-engine fidelity claim is made.

The latest [smoke report](../artifacts/reports/r1-smoke.json) points to the saved local episodes and content-addressed manifest. Raw episodes live under ignored `artifacts/runs/`; fixed regression fingerprints and the compact report/manifest are retained in the project. Smoke elapsed time is a local diagnostic duration, not a training-throughput estimate.
