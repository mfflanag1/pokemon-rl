# M1/G2: batched JAX duel, chance sampler and player views

**The requested fixed-duel port and its scoped checks are implemented. Full G2
remains open.** The scope is exactly `gen9-rattata-duel-v1`: one level-50 Rattata
per side, Run Away, no item, Tackle and Quick Attack, no Tera, no team preview.
This is a development simulator slice, not an official Gen 9 Random Battles engine
or a trained Pokemon policy. The final regression suite passes **173 tests: 63 Node and 110 Python**.
Local CPU was sufficient; no Prime, GPU or final
reserved evaluation games were used.

## What changed

The additive `python/pokemon_jax` package implements integer transitions with JIT,
`vmap` and a four-step `lax.scan`. State has fixed-size HP, PP, winner, turn and
eight public-history rows. Terminal lanes are inert. Priority, critical damage,
rounding, KO cancellation, PP use and winner timing match the pinned reference.
The checked host entry point rejects unsupported profiles, malformed actions,
chance bounds and inconsistent imported history/state before returning a transition.
Internal compiled kernels assume admitted inputs; they are not public untrusted-input
validators. Only two semantic action indices are admitted, mapped to the existing
`move 1` / `move 2` contract.

The prior CPU slice, reference modules, learner and dependency lock remain unchanged.
JAX 0.11.2 / jaxlib 0.11.2 run on CPU with NumPy 2.5.4. New dependencies are pinned
in `requirements-jax.txt`; the installation receipt is retained with the review evidence.

The chance sampler addresses streams by master seed, game ID, turn and event role.
Batch reordering or partitioning preserves each game's outcomes. It uses pinned
Threefry keys, exact power-of-two mappings for damage rolls and tied order, and
uint32 rejection sampling for critical hits. Exactly 4,294,967,280 words are accepted,
with 178,956,970 words per residue modulo 24; the final 16 words are rejected.
The rejection branch has a deterministic injected-word test. These mapping claims
assume uniform PRNG words; empirical tests do not prove universal independence.
JAX documents why naive non-power-of-two `randint` has a slight mapping bias in its
[official API reference](https://docs.jax.dev/en/latest/_autosummary/jax.random.randint.html).

## Evidence and interpretation

| Check | Tested scope | Result |
|---|---|---|
| Damage enumeration | All 32 critical/roll combinations | Exact |
| Existing pinned oracle cases | 10,000 independently seeded games, 31,303 turns, 54,965 hits | Zero JAX transition/event/request disagreements |
| Fresh player-channel cases | 1,000 games, 3,144 turns, 5,512 hits, both seats | Zero semantic view disagreements |
| Player comparisons | 18,000 comparisons including terminal padding; 6,288 live pending-player comparisons | Exact header/history and deterministic logits/value |
| Chance sampler | 262,144 independently addressed game IDs, four turn strata | All predeclared checks pass |
| Statistical family | 592 tests each on JAX draws and fresh Showdown first-turn draws, 1,184 total | No rejection at family alpha 0.01 |

Chance tests cover critical/roll/tie marginals, critical-roll cells, cross-actor cells,
chance-role combinations, disjoint adjacent pairs and turn strata. Each uses an exact
two-sided binomial test; Bonferroni threshold is 0.01 / 1,184. Empty Showdown turn
strata contribute p=1; only first-turn draws are sampled so battle endings do not
introduce outcome-dependent sample sizes. Showdown tied-order checks use the subset
with equal-priority actions. The complete test family, seeds and budgets were fixed
before campaign sampling. The Showdown population includes 105 empty cells and 35 turn-one marginal cells
that duplicate global cells; rare joint events have low detection power at this budget.
Every cell reports its expected count and the p-value if zero events were observed,
so failure to detect a missing rare event is visible. In this run, 401 of 592
Showdown cells cannot reject complete absence at the frozen cutoff (including empty
cells); the larger JAX sample has no such cells. These diagnostics do not alter
the predeclared acceptance threshold. Non-rejection supports these finite checks,
not an all-mechanics or all-distributions proof. No raw-seed equivalence with Showdown is claimed.

There is also a known finite-word distinction: the pinned Showdown `randomChance`
uses `floor(word * 24 / 2^32) == 0`, giving 178,956,971 / 2^32 under uniform words.
The new rejection sampler targets the nominal 1/24 law exactly. The absolute
probability difference is 1 / (3 × 2^32), about 7.76e-11. These tests use the declared
nominal law and cannot resolve that difference. Exact reproduction of Showdown's
finite-word mapping is therefore **not** certified; retain this distinction in any
future G2 promotion decision.

The fresh capture uses upstream's player channel splitter, including only each
player's own requests. A separately implemented Python reducer reconstructs the
semantic view without battle state, RNG, damage-roll labels or opponent requests.
The pinned Custom Game exposes **exact opponent HP**; using percentages here would
be an error. Each view includes relative winner, both HP values, own PP, opponent
move reveals, legal masks and ordered public hit history. History records **HP lost**,
not privileged uncapped damage or a hidden damage roll. Terminal requests can be
stale: terminal views use public events and disable both actions.

Both views remain unchanged after the first hidden submission. Additional tests
vary a canceled opponent choice, canceled chance outcomes and distinct damage rolls
that produce identical public damage, then require identical views and deterministic
actor outputs. Raw state and extra privileged wire keys are rejected at the actor
boundary. These are meaningful restricted information checks, but do not substitute
for the full gate's hidden-set mutation strata. Species, item, ability and Tera are
fixed public profile constants; altered sets fail exact-team admission.

## Performance scope

The receipt includes batch sizes 1, 64 and 1,024, first compilation plus execution,
and 20 synchronized steady-state repetitions. The measured kernel includes sampling,
four padded transition slots and history writes. It excludes reference serialization,
policy inference, training buffers, gradients, optimizer updates and checkpointing.
Accepted run `artifacts/runs/m1-g2-v4` on the local Apple M3 Max CPU:

| Batch | Compile + first run | Median four-turn batch | Games/s, kernel only |
|---:|---:|---:|---:|
| 1 | 292 ms | 0.055 ms | 18,155 |
| 64 | 360 ms | 0.190 ms | 336,399 |
| 1,024 | 350 ms | 1.381 ms | 741,626 |

These are not complete collect/update measurements or a basis for selecting paid hardware.
Re-run on the same pinned environment for comparable measurements; this tiny duel
is not representative of full-format Pokemon cost.

## Remaining gates and next work

Full G2 is **not certified**. Public-view coverage is 1,000 fresh games, whereas the
10,000 older games cover transitions and own-request summaries. The full gate's
1,000 stratified hidden species/set/item/ability/Tera mutations are not provided by
this fixed public-set duel. The slice excludes status, switches, simultaneous fainting,
PP exhaustion, Tera and other mechanics; these need new explicit profile versions,
reachable fixtures and fresh reference evidence before admission. The R6 full-format
unsupported inventory is unchanged. Do not reinterpret this scope as G4 readiness.

Next: port the G1 PPO/GAE learner to JAX autodiff, compare losses/gradients/updates
against the sealed NumPy reference, then connect an observation-only restricted
collector. Establish exact collection/update-boundary resume and measure complete
collect/update cost on CPU. Persistent-game cuts and live-game checkpointing remain
separate work. Only then decide whether a GPU benchmark would save time; Prime remains
optional and unnecessary for the next correctness step. Keep final evaluation sealed.
