# M7: sustained M6 qualification and a small learning screen

This is an additive controller around the sealed M6 policy, collection, target and optimizer kernels. M6 itself has a ten-window budget and is never patched or monkeypatched. M7 owns start/transaction, Session, checkpoint validation/save/load and longer counters. It imports the exact M6 collect/optimize/validate_buffer/observe and policy functions. Tests must reproduce M6's first ten windows bit for bit for all three M6 canary seeds. Qualification checkpoints include both the pre-refill window10 and post-refill window11 states and the final closed cohort. Warm-up uses the same session and excludes its first ten windows from measured counters. Recovery probes execute in-process, are discarded, and their transactions/time are reported separately; the wall interval includes periodic probes and host accounting. RSS includes the runtime/compiler/probes. All session counters are checked on every transaction.

Qualification: one uninterrupted local CPU run, seed 4001, 7,200 measured seconds after ten warm-up windows and compiled recovery probes; finish the current five-window cohort. Retain 30-second telemetry, start/30min/60min/90min/final completed-window checkpoints and original-next-update fingerprints. Monitor finite parameters/metrics, legal actions, bounded values and targets, exact counters, unchanged source/runtime/reservation and a 4 GiB process peak RSS budget. No unaccounted host clock gaps >120 seconds. Replay probes are excluded from training totals. Run a fixed 15-second preflight first; it is not qualification. Training must not stop and restart/stitch to satisfy the clock. Qualification weights are not used in the learning screen.

Learning screen only after qualification passes and exits zero. Three new fixed seeds 1103, 2207, 3301. Each starts from initialization and trains 100 cohorts (500 windows; 3,200 game starts) with unchanged M6 hyperparameters. Compare initialization and the final prescribed endpoint only. No checkpoint/seed selection, hyperparameter tuning, budget extension or outcome-based rerun.

Before production, an explicitly separate end-to-end evidence preflight uses seed4019, ten windows and 32 evaluation pairs per opponent. Its 64 training/384 evaluation games validate the audit and tape machinery, are not interpreted as a learning result, and are excluded from production counts. The qualification remains 7,200 seconds and the production screen remains 500 windows/seed. The generic controller safety ceiling is ten million windows (all derived uint32/int32 counters remain in range); this is not an execution budget. The first 15-second preflight exposed insufficient headroom in the former one-million-window ceiling at the observed CPU rate; the larger safety ceiling prevents a speed-dependent premature stop.

Frozen evaluation opponents: uniform legal random; a frozen policy initialized at seed 6601; and a deterministic player-view-only immediate-damage policy, forced switches chosen by first legal slot. The first two are untrained baselines and the latter is deliberately a narrow baseline, not the full-Showdown tactical bot. Each opponent has 256 paired team/chance clusters, with both seats, per learner seed and endpoint (9,216 evaluation games total). Evaluation uses a separate master key, actor domain and high game IDs. Restricted team identities recur in training and evaluation; this is fresh-game in-distribution evaluation, not held-out-team generalization. Evaluation never contributes gradients and parameter fingerprints must stay unchanged. Every game keeps its 60-turn ceiling, and cutoff is an unresolved outcome, never a draw or loss. Paired common chance/action random addresses support initialization/final comparison.

Use the existing cutoff-aware paired Hoeffding summary with family_size=9, alpha=.05. The independent unit is the pair: averaging the two seats gives a bounded cluster statistic; the formula sqrt(log(9/.05)/(2*256)) uses 256 clusters, not 512 independent games. The difference bound is twice that radius (~.2014). Each seed passes the diagnostic learning gate only if its random-opponent adjusted improvement lower bound is >0 and its worst-case point change against each other frozen opponent is >=-.05. The latter is a noisy point regression guard, not a confidence bound. Overall requires all three seeds. A nonpositive improvement lower bound is inconclusive at this budget, provided the regression guard passes; an integrity failure makes the experiment invalid. Completion and learning success are separate fields. All cells and seeds remain in the report. Report secured wins, losses, cutoffs, bounded-value ranges, decision-weighted value outcome error/calibration (terminal games only, with row counts), actions/entropy, post-turn12 outcomes, parameter change and train/eval counts. No claim of general playing strength.

Freeze the plan, source hashes, runtime, predecessor receipts and final-reservation hashes before production. Review implementation and meaningful tests before launch. Record failed preflights honestly; production never reuses their output directories. Independently replay original-next-update fingerprints at checkpoints and retain evaluation outcome tapes. Keep unrelated full-format and curriculum prototype results separate. Do not modify sealed handoffs or evidence. Public server, final evaluation data and Prime remain unused. Existing GitHub visibility hold remains in force.
